# v0.5 Sandbox Kernel

## 产品方向

v0.5 将目标从“Vue 页面 → 配置 Schema → 再生成页面”调整为“真实 Vue 项目直接运行，代码仍是真相”。

Sandbox 是新的第一层运行时，而 HCP、Component Intelligence、SourceRef 和 Patch Engine 成为其理解和修改能力。

## 核心模型

```text
Real Project
   ↓
Sandbox Kernel
   ├── Package Manager
   ├── Process Lifecycle
   ├── File System
   ├── Edit Intent
   └── Snapshot / Diff / Restore
        ↑
  Human / AI / Visual Inspector
```

### EditIntent

人工编辑和 AI 编辑不要各做一套写入机制。两者都提交 `EditIntent`，由 Sandbox Kernel 进行：

1. source hash 前置条件检查
2. 文件范围限制
3. 原子写入
4. 失败恢复
5. diff 输出
6. HMR / runtime 继续由项目自身负责

## 当前 runtime

v0.5 提供 `LocalSandboxRuntime` 的能力形态，但目前直接内置在 `SandboxSession`：适用于受信任本地项目开发。

浏览器 WebContainer 和远程 container/VM 应该作为同一个 Runtime Adapter 契约的后续实现，不应该把 WebContainer 写死进核心模型。

## Snapshot

Snapshot 只保存源文件，不复制 `node_modules`、`dist`、`.git` 和 `.hcbridge`。恢复时只作用于沙盒管理的文件集合，避免破坏依赖缓存和平台元数据。

## Gateway

`apps/sandbox` 提供一个最小 HTTP gateway：

- `/api/sessions/:id/status`
- `/api/sessions/:id/files`
- `/api/sessions/:id/file`
- `/api/sessions/:id/start`
- `/api/sessions/:id/stop`
- `/api/sessions/:id/edit-intent`
- `/api/sessions/:id/snapshot`
- `/api/sessions/:id/restore`
- `/api/sessions/:id/diff`

这层将来可以被 Monaco、平台 Inspector 或 AI Agent 直接复用。

## 已知边界

- 当前本地 runtime 是受信任执行，不是多租户安全隔离。
- 尚未把浏览器 DOM 节点反向映射到 Vue SFC SourceRef。
- 尚未接入具体 LLM Provider；AI 只定义 EditIntent 协议。
- 当前工作台使用浏览器原生编辑控件，Monaco 属于下一层 UI。
