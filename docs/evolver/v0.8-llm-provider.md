# v0.8 LLM Provider + Safe Plan Validation

v0.8 把 v0.7 的 AgentProvider 真正接到“外部 LLM”这一层，但不把任何厂商 SDK 写死在沙盒内。

## 架构

```text
Preview Inspect
     ↓
AgentContext
     ↓
LLM Provider
     ↓
JSON AgentPlan
     ↓
Plan Validator
     ↓
EditIntent + current source hashes
     ↓
Snapshot → Patch → Verify → Rollback
```

## Provider

`@hcbridge/llm-provider` 提供 `OpenAICompatibleAgentProvider`，使用普通 HTTP JSON 请求，不依赖厂商 SDK。

环境变量：

```bash
HCBRIDGE_AGENT_ENDPOINT=https://your-llm-endpoint/v1/chat/completions
HCBRIDGE_AGENT_API_KEY=...
HCBRIDGE_AGENT_MODEL=your-model
HCBRIDGE_AGENT_TIMEOUT_MS=60000
```

未配置 endpoint/model 时，沙盒继续使用 `heuristic-local`，保证本地闭环无需密钥即可测试。

## 安全边界

LLM 不直接拥有文件系统写权限。它只能提交结构化计划。

当前 provider 只允许 `replace-text`，并且：

- 文件必须存在于 Agent 提供的上下文中
- `oldText` 必须在当前源码中存在
- 多次命中必须显式提供 `occurrence`
- 每个修改文件由服务端重新计算 `expectedHash`
- 单次最多 8 个操作
- 单段替换文本最多 8000 字符
- Apply 前 Snapshot
- typecheck/build 失败自动回滚

因此即使 LLM 返回错误计划，也不能绕过 Sandbox Kernel 的 hash guard 和路径约束。

## 上下文

当前 Context Pack 包含：

- 用户请求
- Inspector 结果
- 当前选中源码及 SourceCandidate
- package scripts
- 选中源码直接引用的少量本地文件
- Source is Truth / minimal patch 约束

这是 v0.8 的第一版“项目上下文”，后续可继续加入组件契约、语义图、运行时 trace、Git diff 和错误日志。

## CLI

```bash
pnpm run cli -- agent-plan fixtures/agent fixtures/agent/button.json "把这个按钮改成 dashed"
pnpm run cli -- agent-context fixtures/agent fixtures/agent/button.json
```

配置 Provider 后，上面的 `agent-plan` 会自动使用外部 LLM；没有配置时会回退到本地 heuristic provider。

## 当前明确不做

- 不允许 LLM 任意执行 shell
- 不允许 LLM 任意写整个项目
- 不允许模型直接操作宿主文件系统
- 不在浏览器端暴露 API Key
- 不依赖某一个厂商 SDK
- 不承诺一次自然语言输入即可完成复杂跨模块重构

下一阶段重点是多文件 Patch 规划、运行时验证和错误自修复，而不是继续扩大“模型能改什么”的权限。
