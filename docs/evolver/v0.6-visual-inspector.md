# v0.6 Visual Inspector

v0.6 把真实运行中的 Preview 与源码连接起来，但不承诺“DOM 100% 精准映射源码”。

## 核心模型

```text
Runtime DOM
   ↓ postMessage probe
Inspector Bridge
   ↓
Visual Inspector
   ↓
scan *.vue + Vue Template AST
   ↓
Candidate ranking
   ↓
exact / relocated / ambiguous / lost
   ↓
SourceRange
   ↓
Editor selection
```

## 为什么先做候选定位

运行时 DOM 和 `.vue` template 不是同构关系：组件可能产生多个 DOM、slot 会改变结构、`v-if` / `v-for` 会改变实例数量、第三方组件还可能渲染完全不同的根节点。因此 v0.6 不伪造绝对映射。

定位证据目前包括：

- DOM tag 与 template tag / component alias
- `id`
- class
- 静态 attributes
- href
- 文本内容
- 已观测的祖先 tag

结果保留候选集合和 confidence。

## 当前安全语义

- `exact`：证据充分且领先候选明显，不需要猜测即可定位。
- `relocated`：存在高质量唯一候选，但不是强身份匹配。
- `ambiguous`：多个候选无法安全区分，不自动选择。
- `lost`：没有达到最低证据阈值。

`ambiguous` / `lost` 只展示候选或诊断，不自动修改源码。

## Sandbox 集成

`apps/sandbox` 通过同源 gateway 的 `/preview/:sessionId/` 代理真实 Vite Preview，并在 HTML 中注入轻量 Inspector Bridge。

Bridge 不读取或修改 Vue 内部状态，只采集 DOM 特征，通过 `window.parent.postMessage` 把点击目标发送回工作台。

工作台调用：

```text
POST /api/sessions/:sessionId/inspect
```

服务端扫描当前项目 `.vue` 文件并返回候选 `SourceCandidate`。

## 当前限制

Preview proxy 当前只代理 HTTP 请求，不做代理 WebSocket，因此 Inspector 模式下不保证 Vite HMR。停止 Inspector 或直接访问真实 Preview URL 可继续使用标准 HMR。

后续 v0.7 应接入更强的运行时组件身份信息，再把自然语言请求 → EditIntent → Patch → Runtime Verify 串起来。
